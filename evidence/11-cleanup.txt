---------------------------------------------------------------
STEP: Remove the AppProject and the Argo CD ingress
---------------------------------------------------------------

  # Both were applied by hand during bootstrap, so neither is owned by an

  # Application and neither is removed by the cascade.

  # Order matters, and getting it wrong deadlocks the cluster. An Application

  # carrying the resources-finalizer cannot finish deleting unless the

  # controller can still resolve its AppProject; delete the project first and

  # the Application hangs in Terminating forever, the project hangs on its own

  # finalizer waiting for the Application, and the only way out is to patch

  # the finalizers off both by hand. Hence the wait loop above, and the guard

  # below: the project is only removed once every Application is actually

  # gone.

  # The same deadlock used to be unavoidable, because the project lived in

  # gitops/apps/ and was therefore managed by the root Application - which

  # also referenced it. Deleting the root required deleting the project,

  # deleting the project required no Application to reference it, and the

  # referencing Application was the root. It now lives in gitops/bootstrap/,

  # outside anything Argo CD manages, so the cascade can complete.

$ kargo delete appproject cse644 --ignore-not-found
appproject.argoproj.io "cse644" deleted from argocd namespace

$ kargo delete ingress argocd-server --ignore-not-found
