---------------------------------------------------------------
STEP: Serve the UI over plain HTTP behind the ingress controller
---------------------------------------------------------------

  # argocd-server terminates TLS itself by default and redirects HTTP to

  # HTTPS. Behind an ingress that also handles TLS the result is a redirect

  # loop. server.insecure=true hands TLS termination to the ingress - which

  # on this local cluster means plain HTTP on localhost, a limitation of the

  # environment that is recorded in the README rather than hidden.

$ kargo patch configmap argocd-cmd-params-cm --type merge -p '{"data":{"server.insecure":"true"}}'
configmap/argocd-cmd-params-cm patched

---------------------------------------------------------------
STEP: Read-only anonymous access to the UI
---------------------------------------------------------------

  # So the dashboard and application tree can be screenshotted and reviewed

  # without a password existing anywhere in this repository or in these

  # transcripts. The default role is readonly: an anonymous visitor can look

  # at everything and change nothing. This is acceptable because the cluster

  # listens on localhost only; it would not be on a reachable network.

$ kargo patch configmap argocd-cm --type merge -p '{"data":{"users.anonymous.enabled":"true"}}'
configmap/argocd-cm patched

$ kargo patch configmap argocd-rbac-cm --type merge -p '{"data":{"policy.default":"role:readonly"}}'
configmap/argocd-rbac-cm patched
