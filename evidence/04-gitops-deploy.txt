  # A Kubernetes Secret is base64-encoded, not encrypted. Committing one to a

  # public repository publishes it. Both Secrets below are generated here and

  # never leave the cluster; only their key names and lengths are printed.

  # The honest cost: these two objects are outside GitOps control, so Argo CD

  # can neither recreate them nor detect drift in them. Sealed Secrets or the

  # External Secrets Operator is the production answer - see the README.

STEP: Bootstrap 1 of 2: the AppProject
---------------------------------------------------------------

  # Argo CD will not admit an Application whose project does not exist, so

  # the project has to exist before anything else. It lives in

  # gitops/bootstrap/ and NOT in gitops/apps/, which is the directory the

  # root Application syncs, and that placement is a correctness requirement

  # rather than tidiness.

  # When the project was in gitops/apps/ the root Application managed it -

  # and also used it, because the root Application's own spec.project is

  # cse644. Deleting the root then deadlocked permanently: its finalizer has

  # to delete everything it manages, which includes the project, and Argo CD

  # will not delete a project while an Application still references it. The

  # referencing Application was the one being deleted. scripts/cleanup.sh

  # sat at 'applications=1' until it was patched out by hand.

  # Bootstrap objects are created by hand and removed by hand; only the two

  # child Applications are managed.

STEP: Every object Argo CD created carries a tracking annotation
---------------------------------------------------------------

  # This is how prune knows what it owns. Argo CD v3 tracks by annotation

  # rather than by the app.kubernetes.io/instance label it used historically,

  # and the difference matters here: the annotation records the application

  # name, the group and kind, and the namespace and name, so the controller

  # can distinguish an object it created from an identically-named object it

  # merely found. A label carrying only an application name cannot, and it

  # also collides with the perfectly ordinary app.kubernetes.io/instance the

  # workload itself might want to set.

$ kn get deploy,svc,ingress,cm -o custom-columns='KIND:.kind,NAME:.metadata.name,TRACKED-BY:.metadata.annotations.argocd\.argoproj\.io/tracking-id'
